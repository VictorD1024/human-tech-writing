# Human Writing

一个让 AI 少说套话、写得更具体的中文写作 Skill。

它不靠“请写得自然一点”这种抽象要求，而是检查四件事：信息密度、结构节奏、判断边界和事实来源。最重要的原则是：**没有材料，就不要靠编造细节制造人味。**

## 能做什么

- 从事实清单起草报告、文章、周报、备忘录或邮件
- 重写已有 AI 稿，删除空话和机械结构
- 只调整语气，不改变原有结构和论点
- 在交付前执行一套可检查的自检规则

## 安装

将仓库克隆到 Codex skills 目录：

```bash
git clone https://github.com/YOUR_NAME/human-writing.git ~/.codex/skills/human-writing
```

重启 Codex，或开启一个新会话，然后直接描述写作任务。也可以显式调用：

```text
使用 $human-writing 重写这份周报。保留所有数字，不要添加新事实。
```

仓库发布后，把上面的 `YOUR_NAME` 替换成实际 GitHub 用户名。

## 示例

原文：

> 随着数字化时代的不断发展，系统性能优化变得至关重要，能够显著提升用户体验。

有事实材料时：

> 这次改动把首页加载时间从 3.2 秒压到 0.9 秒。客服记录里，与“页面打不开”有关的工单随后少了 41%。

没有事实材料时，Skill 不会补数字：

> 这次改动缩短了首页加载时间，但现有材料没有给出具体幅度，也无法判断它对工单量的影响。


## 设计原则

1. 事实优先：不编造数字、案例、引语和来源。
2. 最小改动：只调语气时，不擅自重构文章。
3. 规则可检查：避免只写“自然”“生动”之类无法验收的要求。
4. 禁词不是目的：词语有实际含义时可以保留，空泛时才删除或具体化。
