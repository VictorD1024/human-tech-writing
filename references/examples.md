# AI 句式、技术黑话与缩写改写

以下例子展示表达方法，不提供可复用的系统事实。改写用户文档时，只能使用用户材料中已经存在的行为、字段、数字和结果。

## 伪纠偏：“不是 A，而是 B”

改写前：

> 角色是权限边界，不是三个实现类。

材料能确认两者关系时：

> 角色决定用户可以执行哪些操作。当前代码用三个类实现这套权限规则；类的数量属于实现细节，不影响权限模型。

原句制造了对立，却没有解释“权限边界”和“实现类”怎样关联。只有当 B 是读者容易产生的真实误解，并且这个误解会影响设计或操作时，才需要用否定句纠正。

## 复述式结论

改写前：

> 请求进入队列后由 Worker 处理。这意味着系统采用异步处理模式。

材料包含客户端行为时：

> 接口收到请求后立即返回任务 ID，Worker 随后从队列中取出任务。客户端需要用任务 ID 查询执行状态，不能从首次响应中取得最终结果。

“这意味着”后面若只给前一句贴标签，可以删除。若异步处理会改变调用方式、状态查询或失败处理，应直接写出这些后果。

## 模糊的能力声明

改写前：

> 调度器支持自动重试，保证任务可靠执行。

材料完整时：

> 调度器在任务请求超时后最多重试 3 次，每次间隔 10 秒。3 次都失败后，任务状态变为 `failed`，不再继续执行。

“支持”“自动”和“保证”容易掩盖触发条件、次数、停止条件和最终状态。材料没有这些信息时，应提出缺口，不得套用示例数字。

## 为整齐而拆分

改写前：

> 该模块具有三个核心能力：统一入口、灵活扩展和高效执行。

如果材料只确认入口行为：

> 所有任务都从 `/tasks` 接口提交。

不要为了三点式结构保留无法验证的“灵活”和“高效”。段落数量和长度应由实际信息决定。

## “落盘”

改写前：

> 中间结果会定期落盘，避免任务失败后丢失。

材料完整时：

> Worker 每处理 1,000 条记录，就把当前偏移量写入对象存储。任务重启后从最后一次成功写入的偏移量继续处理，最多重复 999 条。

要补齐的信息：谁写、写到哪里、写什么、何时写、失败或重启后怎样读取。材料没有这些信息时，不得照抄示例数字。

## “契约”

改写前：

> 上下游通过稳定的数据契约完成解耦。

材料完整时：

> 生产者按照 `event-v2` 的 JSON Schema（一份机器可读的字段定义）发送事件。消费者只依赖其中标为必填（required）的 4 个字段；新增可选字段不要求消费者同步发布。

“契约”可以是准确术语，但需要说明载体是什么、约束什么、如何处理变更。

## “冒烟”

改写前：

> 上线后先跑冒烟，确认无误再全量。

材料完整时：

> 先把新版本部署到 5% 的实例，并运行 3 项最小检查：健康检查返回 200、测试账号可以登录、创建订单接口成功写入一条记录。三项都通过后再扩大流量。

“冒烟测试（smoke test）”指快速验证关键路径是否能工作的最小测试集。文档还应列出本系统实际检查什么，以及怎样算通过。

## 缩写堆叠

改写前：

> RAG 服务通过 MCP 调用 LLM，并用 RRF 合并 BM25 与 ANN 的 Top-K 结果。

面向相邻领域工程师：

> 检索增强生成（Retrieval-Augmented Generation，RAG）服务先执行两种检索：BM25 关键词检索和近似最近邻（Approximate Nearest Neighbor，ANN）向量检索。接着，服务用倒数排名融合（Reciprocal Rank Fusion，RRF）合并两路结果，把排名最高的 K 条文档交给大语言模型（Large Language Model，LLM）生成答案。外部工具调用采用模型上下文协议（Model Context Protocol，MCP）。

面向熟悉检索的团队：

> RAG 服务分别执行 BM25 和 ANN 检索，再用 RRF 合并两路 Top-K 结果；合并结果随请求发给 LLM。外部工具调用走 MCP。

同一句话应随读者变化，而不是固定要求展开所有缩写。

## 模糊的性能声明

改写前：

> 新架构提供生产级的高性能和高可用能力。

有测量结果时：

> 在 800 请求/秒的压测下，接口的 p95 延迟为 120 毫秒，也就是 95% 的请求能在 120 毫秒内得到响应。单个可用区下线后，流量在 45 秒内切换到其余两个可用区；切换期间错误率最高为 0.8%。

没有测量结果时：

> 新架构增加了跨可用区副本和自动流量切换，但目前没有压测或故障演练结果，无法确认性能和恢复时间。

## 多页面教程中的缩写

目录页：

> 第 3 章介绍监督微调（Supervised Fine-Tuning，SFT）和基于可验证奖励的强化学习（Reinforcement Learning with Verifiable Rewards，RLVR）。

第 3 章仍应在首次出现时展开这些缩写，因为读者可能通过搜索或外部链接直接进入该页。只有页面始终作为同一连续文档的一部分呈现时，才可以依赖前文定义。

## 保护代码和字段

原文：

> 请求缺少 `task_id` 时返回 HTTP 400，错误体中的 `retryable` 为 `false`。

改写时可以解释这些字段的作用，但不能把 `task_id` 改成更“自然”的名称，也不能替换状态码或布尔值。若怀疑原文有误，应标记待确认，而不是静默修正。
