# 可复制的中文提示词

## A：重写技术文档

```text
请把下面内容重写成技术人员能快速阅读、外行人也能跟上的技术文档。保留准确术语，但把“落盘、契约、冒烟、链路、打通、兜底”等内部黑话落实为具体对象、触发条件、动作和可观察结果。不常见缩写第一次出现时写出中英文全称，并用一句话说明它在本文中的作用；只出现一次且全称不长时，不引入缩写。开头说清问题、范围和读者能完成什么，正文先讲主流程和关键边界，再放参数、异常和实现细节。不要编造接口行为、字段、状态码、性能数据或测试结果；材料不足就明确标注待确认。
```

## B：面向跨领域读者解释

```text
请保留这份技术文档的专业精度，同时增加跨领域读者继续阅读所需的最少解释。不要把正文改成科普文章。第一次出现的陌生概念用一句就地解释；组件之间写清谁调用谁、数据往哪里走、失败时发生什么。缩写不要堆叠，必要时增加一个短词汇表。技术人员应能跳过解释直接找到接口、步骤、边界和风险，非技术读者应能看懂问题、方案和影响。不得添加材料中不存在的系统行为。
```

## C：审查技术黑话和缩写

```text
请审查下面的技术文档，只列出会阻碍阅读的内部黑话、歧义术语和未解释缩写。对每一项说明：原词、为什么难懂、需要补充的具体信息、建议改写。不要因为词语听起来专业就删除；如果它在本文中含义精确，只需建议首次出现时如何解释。无法确认的缩写不要猜。
```
